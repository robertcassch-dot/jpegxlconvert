Does Chrome Support JPEG XL?

Not by default — not yet. Chrome 145 quietly brought the JPEG XL decoder back in February 2026, but it sits behind a flag and is still switched off in Chrome 151. Here's exactly where things stand, and how to turn it on right now.

The short answer

Chrome can decode JPEG XL today, but it won't unless you ask it to. In December 2025 Google vendored jxl-rs — a memory-safe Rust decoder from the official libjxl organisation — into Chromium. It was wired up in January 2026 and shipped to the stable channel with Chrome 145 on 10 February 2026, hidden behind the enable-jxl-image-format flag.

That is where it has stayed. As of July 2026, Chrome 151 still has JPEG XL disabled by default — five stable releases after the decoder landed. So if you put a .jxl image on a web page today, virtually nobody using Chrome will see it.

This is the detail most headlines get wrong. "JPEG XL is back in Chrome" is true about the code and misleading about the experience. Shipped ≠ enabled.

How to enable JPEG XL in Chrome

Takes about fifteen seconds. It affects your browser only — visitors to your site are unaffected.

Open the flags page

Paste chrome://flags/#enable-jxl-image-format into the address bar and press Enter. The flag will be highlighted.

Switch it to Enabled

Use the dropdown next to "Enable JPEG XL image format" and pick Enabled.

Relaunch Chrome

Click the Relaunch button that appears. Chrome now renders .jxl images natively.

The same steps work in Edge, Brave, Opera and Vivaldi — they all build on Chromium, so they inherit both the decoder and the flag. Use edge://flags, brave://flags and so on.

One catch worth knowing: a flag is not a promise. Chrome flags get renamed and removed between versions, and enabling one only changes your own machine. If you need a .jxl to open reliably — on someone else's computer, on a phone, in an email — don't rely on it. Open the file in our viewer or convert it to JPG instead.

How JPEG XL got here

🧪

2021 — first arrival

Chrome 91 shipped an experimental JPEG XL decoder behind a flag. Optimism was high.

🗑️

2022 — removed

Google announced it was pulling JPEG XL, citing insufficient ecosystem interest. The code was gone by Chrome 110. The decision was deeply unpopular.

📄

2025 — the PDF turn

The PDF Association named JPEG XL its preferred HDR format for PDF. Chrome's built-in PDF viewer would need a decoder to stay compliant.

🦀

Dec 2025 — a Rust decoder

Google vendored jxl-rs into Chromium. Choosing Rust over the C++ libjxl answered the memory-safety objection that helped kill it the first time.

🚢

Feb 2026 — Chrome 145

The decoder reached the stable channel on 10 February, behind enable-jxl-image-format.

⏳

Now — waiting

Chrome 151 and still off by default. Google has not published a date for flipping the switch.

When will it be on by default?

Nobody outside Google knows, and we would rather say that than invent a date. The widely repeated expectation is the second half of 2026, but that expectation has already slipped once: the decoder has been sitting in stable Chrome since February without being switched on.

What we can say is what the remaining blockers look like. The Rust decoder currently runs within roughly 15–25% of the speed of the C++ reference implementation, and a format that decodes slower than the one it replaces is a hard sell for a browser that competes on page-load metrics. Encoding, colour management and the fuzzing bar for a decoder exposed to the open web all have to clear review too.

The day it does flip, though, the change is abrupt: Chrome and Edge together would take JPEG XL from roughly 15% of browsers to somewhere near 90% in the space of a few weeks.

FAQ

Does Chrome open .jxl files in 2026?
Only if you enable the flag yourself. Out of the box, Chrome 151 will download a .jxl file rather than display it. Our JPEG XL viewer opens it without touching any settings.
Is the flag safe to turn on?
It is an official Chrome flag using Google's own Rust decoder, so it is not a hack or an extension. It is still pre-release plumbing, though — expect the occasional rough edge, and expect the flag to change name or disappear between versions.
Why did Google remove JPEG XL in the first place?
In 2022 Google said the format did not bring enough incremental benefit over existing formats to justify maintaining it. Memory safety in the C++ decoder was a recurring concern too — which is why the format returned on the back of a Rust rewrite.
Does Edge support JPEG XL?
Edge is built on Chromium, so it has exactly the same decoder behind exactly the same flag, at edge://flags/#enable-jxl-image-format, and the same default-off behaviour.
What about Firefox?
Firefox has had an implementation in progress for a long time and keeps it disabled in stable builds. Mozilla's stated interest improved once a memory-safe decoder became realistic, but there is no shipping date.
Should I convert my photos to JPEG XL now?
For personal storage and archiving, it already makes sense — especially lossless JPEG re-packing, which shrinks files with no quality change at all. For images you publish on the web, keep a JPEG, WebP or AVIF fallback until Chrome flips the switch.
